# 保存助手 · 电脑端传输工作台

手机把抖音/视频号作品传到这台电脑，就靠这个程序在后台收。

## 现在是「后台常驻 + 开机自启」

装了开机自启之后，**你不需要做任何事**：

- 开机登录 Windows 后，它会自己在后台起来（无窗口、无弹窗、不开浏览器）
- **关掉任何窗口都不会影响接收** —— 服务不在窗口里，它是独立后台进程
- 想看界面时，双击桌面「保存助手 传输工作台」即可打开

## 常用操作

需要手动管的时候，在本目录下开命令行：

```bat
python tools\autostart.py status      查看：自启是否已装、服务是否在跑
python tools\autostart.py start       立刻后台起服务（不开浏览器）
python tools\autostart.py stop        停掉正在跑的服务
python tools\autostart.py install     装开机自启
python tools\autostart.py uninstall   取消开机自启
```

`status` 的典型输出：

```
开机自启：已安装
  命令："...\pythonw.exe" "...\server.py" --background
服务状态：正在运行（PID 12345，端口 18765）
```

## 传输页

手机传过来的文件在这里看，三条行为值得知道：

- **传输队列按 id 归并**：一次传输只有一条记录，从「进行中」直接变成「已完成」。
  （早先有个 bug 会让它裂成两条，一条永远停在「正在接收」—— 已修，并有回归测试锁住。）
- **列表跟着磁盘走**：服务每 5 秒重扫一次接收目录。你在资源管理器里**删掉**或**移走**某个文件，
  列表里那条会在几秒内自动消失，不会留下一个点了没反应的死记录。
- **设备名会保留**：重扫时会把「哪台手机传的」从内存里合并回去，
  所以不会出现「设备名刚显示就变成 —」。

## 下载页

工作台顶部有两个标签：

- **传输**：局域网收文件界面，手机传过来的文件在这里看。
- **下载**：在电脑上直接解析并保存抖音 / 西瓜 / 微信视频号的内容。

用法是**解析 → 勾选 → 保存**：粘贴链接点「解析」，等它把作品里的
视频 / 图片 / 实况 / 配乐 / 封面列出来，勾上要的再点「保存选中」。

保存位置按类型分目录（和手机传输保持一致）：

| 内容 | 落到 |
|---|---|
| 视频、实况、拼图 | `接收目录\video\` |
| 图片 | `接收目录\image\` |
| 配乐（音频） | `接收目录\audio\` |
| 封面 | `接收目录\cover\` |

### 保存选项

| 选项 | 说明 | 需要 ffmpeg |
|---|---|---|
| 把封面写进视频 | 只改元数据，秒级 | 是 |
| 把标题烧进视频 | 整段重编码，**很慢**，只在明确需要时才勾 | 是 |
| 把贴纸合成进图片 | 平台没下发合成图时才起作用 | 是 |
| 把选中的图片拼成一个视频 | 多张图 → 一个 mp4 | 是 |

**没装 ffmpeg 也能用**：不勾这些选项时，视频、图片、配上音轨的直链都能正常保存；
勾了但缺 ffmpeg 会明确告诉你是哪一步没做，而不是给你一个看起来处理过其实没有的文件。

### 微信视频号的登录态

视频号的视频地址只在带登录态时下发，所以要先在下载页的「视频号登录态」
里粘贴一次浏览器请求：

1. 浏览器登录 `yuanbao.tencent.com`
2. 按 F12 打开开发者工具 → Network
3. 随便点一个 `api` 请求 → 右键 → Copy → **Copy as cURL**
4. 粘贴进输入框，点「保存并校验」

保存后会立刻走一次完整链路校验能用。**凭据只存在本机 `config.json` 里，不上传任何地方。**
失效了重新粘一次即可。

抖音不需要登录态，这一步可以跳过。

## 文件都放哪

| 文件 | 作用 |
|---|---|
| `server.py` | 服务本体：托管界面 + 局域网收文件 + UDP 发现 |
| `download_engine.py` | 下载编排：解析 → 勾选 → 保存，屏蔽两个平台的差异 |
| `dy_sign.py` | 抖音 `a_bogus` 签名（照手机端移植） |
| `dy_parse.py` | 抖音解析：详情接口 + 分享页四种兜底格式 |
| `wx_parse.py` | 微信视频号解析 + 登录态归一化 |
| `media_ff.py` | 转码类功能（抽音轨 / 烧标题 / 封面 / 贴纸 / 拼图），全部走 ffmpeg |
| `config.json` | 端口、接收目录、视频号登录态 |
| `server.log` | 运行日志（出问题先看这个） |
| `server.lock` | 记录当前服务的 PID，用于防止重复启动（正常退出会自动删） |
| `static\` | 工作台前端（index.html / app.js / style.css） |

## 出问题时

1. **手机连不上** → 先跑 `python tools\autostart.py status` 确认服务在跑；
   不在跑就 `start` 一下。
2. **服务起不来** → 看 `server.log` 最后几行，那里会写明确原因。
3. **端口被占** → 改 `config.json` 里的 `port`，手机端会通过 UDP 广播自动跟上。
4. **换电脑后自启失效** → 自启项里写死了绝对路径，换目录后要重跑一次 `install`。
5. **解析失败** → 看 `server.log`，会写明是哪一步（详情接口 / 分享页 / 登录态）。
   抖音的页面结构和接口几个月就会变一次，解析失败通常是这个原因。

## 自启项写在注册表哪里

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
    值名：SaveAssistantTransfer
```

写在当前用户下，**不需要管理员权限**，也不影响这台机器的其他用户。

## 设计上的几个取舍（改之前先看）

- **常驻进程用 `pythonw.exe`，不是 `python.exe`、更不是 `cmd.exe`。**
  Windows 防火墙的入站允许规则是按**可执行文件**匹配的，之前已经针对
  `pythonw.exe` 放行过；换宿主会重新撞防火墙，表现为手机连不上。
  而且 `pythonw` 无控制台，天然不会有「关窗口 = 关服务」这个问题。
- **后台模式（`--background`）绝不弹窗。** 用户没在看，一个错误框会一直堵在桌面上。
  后台模式下的致命错误只写进 `server.log`。
- **单实例靠锁文件，不靠端口占用。** 只靠端口的话，用户点快捷方式只会看到
  「浏览器开了但没反应」，不知道背后是谁在服务；现在会明确记一行日志并直接开界面。
- **陈锁必须能自愈。** 进程被强杀时锁文件会留下，如果不清理，
  下次启动就会被一个死 PID 永久挡住。
